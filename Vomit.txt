Eli siis: Kun ajoimme docker compose up -d - docker teki asiat docker-compose.yml-tiedoston perusteella:
Se latasi internetistä Postgre: 15-alpine. Käynnisti imagen. "Porttiohjauksen" Port Mapping - Tietokanta kontin sisällä kuuntelee porttia 5432. docker-compose.yml sisällä on rivi: ports: - "5432:5432", tämä tarkoittaa, että kontin SISÄINEN portti kuuntelee porttia 5432 ja kytkee sen Windows-isäntäkoneen (tai linux) porttiin 5432.

Eli nyt spring-boot, joka on kontin ulkopuolella windowsin puolella, pääsee portin 5432 kautta käsiksi dockerin sisällä sijaitsevaan konttiin (postgre).

Kun juoksutin mvnw spring-boot:run, seuraavat asiat tapahtuivat ketjussa:
Javan virtuaalikone käynnistyi. Spring luki profiilit 'application.yml' ja näki 'active: dev'. Tämän jälkeen spring latasi 'application-dev.yml' -tiedoston ja luki sen asetukset. Spring myös näki pom.xml, missä on riippuvuuden (postgresql) ja latasi ajurin joka keskustelee PostgreSQL:n kanssa.

Spring lukee konfiguraatio osoitteen: jdbc:postgresql://localhost:5432/harjoitusdb, eli protoclla on Postgresql. Host on localhost (tämä kone). Portti: 5432. Tietokanta/database: harjoitusdb.

Nyt spring avaa TCP/IP-verkkoyhteyden annettuun Hostiin ja Porttiin: localhost:5432, eli portti mikä on auki dockkeriin.

import org.springframework.beans.factory.annotation.Autowired;
import org.springframework.web.bind.annotation.*;

Käydään vielä tiedostot lävitse, että kaikki on itsestään selvää:
Note.java: eli siis Entity. Tämä tiedosto itsessään ei tee mitään. Näyttää miltä datan pitäisi näyttää.
Se kommunikoi Hibernate (springin sisäinen apuri) kanssa ja käskee sitä luomaan SQL-taulun annotaatioiden avulla:

Esim. '@Entity' -> 'public class Note'= Luo taulu jonka nimi on: 'note'
      '@Id' -> Tämä muuttuja (private Long id;) on PrimaryKey
      '@GeneratedValue(strategy = GenerationType.IDENTITY) -> 'Postgre, luo automaattinen arvo id:lle'
      'private String content -> Tämä on "sarake" pöydän sisällä.

NoteRepository.java - ns. tulkki:

Tämä on 'Interface'. Ei koodia, pelkkä määrittely.
Tämä toimii tulkkina Javan ja SQL:n välillä. Luodaan lennossa käynnistyksen yhteydessä.

Esim. 'extends JpaRepository<Note, Long>' -> 'Javalla on Note ja se tyyppiä Long (numero).

TestController.java - Kontrolleri - Hallintakeskus:
'@Autowired private NoteRepository noteRepository'
Täälä tapahtuu paljon Dependency Injection (DI) ja se on hieman abstraktoitua.
Spring Boot etsii käynnistyksessä luomansa Repository-olion ja "tiputtaa" sen tähän muuttujaan. Ilman tätä riviä yhteys tietokantaan puuttuisi tästä tiedostosta.

addNote(@RequestBody String content) -funktio:

Luodaan CI-putki (Continuous Integration):

Luo .github/workflows

mkdir .github
cd .github
mkdir workflows
cd workflows

Tee tänne (workflows) main.yml:


name: CI/CD Pipeline

# Milloin robotti herää?
on:
  push:
    branches: [ "main" ]
  pull_request:
    branches: [ "main" ]

jobs:
  build-and-test:
    runs-on: ubuntu-latest
    
    steps:
    # 1. Hae koodi repositoriosta
    - uses: actions/checkout@v4
    
    # 2. Asenna Java 17 (sama kuin koneellasi)
    - name: Set up JDK 17
      uses: actions/setup-java@v4
      with:
        java-version: '17'
        distribution: 'temurin'
        cache: maven

    # 3. Anna suoritusoikeudet Maven-wrapperille (tärkeä Linux-ympäristössä)
    - name: Grant execute permission for mvnw
      run: chmod +x mvnw

    # 4. Aja testit käyttäen 'test'-profiilia
    # Tämä käyttää application-test.yml -tiedostoa ja H2-tietokantaa
    - name: Run Tests
      run: ./mvnw test
      env:
        SPRING_PROFILES_ACTIVE: test


Tämä on resepti, jota GitHubin palvelimet noudattavat.
"SPRING_PROFILES_ACTIVE: test" selitettynä: 
"Koska GitHubin virtuaalikoneella ei ole Docker-PostgreSQL:ää käynnissä (kuten sinun omalla koneellasi on),
meidän täytyy käyttää application-test.yml-tiedostossa määriteltyä H2-tietokantaa. Se on "muistissa" toimiva tietokanta, joka ei vaadi asennuksia."

  build-and-deploy:
    runs-on: ubuntu-latest

    steps:
    - uses: actions/checkout@v4

    - name: Set up JDK 17
      uses: actions/setup-java@v4
      with:
        java-version: '17'
        distribution: 'temurin'
        cache: maven

    - name: Grant execute permission for mvnw
      run: chmod +x mvnw

    # 1. Aja testit (Varmistetaan että koodi toimii)
    - name: Run Tests
      run: ./mvnw test
      env:
        SPRING_PROFILES_ACTIVE: test

    # 2. Paketoi sovellus (Luo .jar tiedoston target-kansioon)
    - name: Build Application JAR
      run: ./mvnw package -DskipTests

    # 3. Kirjaudu Docker Hubiin (Käyttää tallentamiasi salaisuuksia)
    - name: Log in to Docker Hub
      if: github.event_name != 'pull_request'
      uses: docker/login-action@v3
      with:
        username: ${{ secrets.DOCKER_USERNAME }}
        password: ${{ secrets.DOCKER_PASSWORD }}

    # 4. Rakenna Docker-image ja lähetä se (Push)
    - name: Build and Push Docker image
      if: github.event_name != 'pull_request'
      uses: docker/build-push-action@v5
      with:
        context: .
        push: true
        tags: kaikatajisto/ohjelmistotuotanto-harjoitus:latest
